# Project outcomes

- [x] **Inspect and fix the uploaded baby-action-ai project.** “check this file, fix it” — inspect the uploaded project and correct the defects that prevent the requested website behavior while preserving the supplied trained model and existing project stack.
- [x] **Select, preview, replace and remove photos.** “when we upload photos of babies” — accept drag-and-drop and file browsing for JPEG, PNG and WebP still photos, display a preview with replace and remove controls, and show clear guidance for missing, empty, unsupported, unreadable or oversized files. The browser picker/drop target and controls must be keyboard accessible. Full-body framing is helpful, but not mandatory when a supported pose's relevant landmarks remain clear.
- [x] **Return a truthful pose estimate for each photo.** “it should determine wheter the baby is standing, sitting, or whatever action it is doing.” Analyze each uploaded image with the supplied pose detector and classifier; report supported postures (standing, sitting, on all fours, on the tummy, on the back) or a clear unknown/ambiguous/no-pose state. Never invent an open-ended activity label, and do not let a photo inherit a prediction from another photo. Treat all-fours as a still posture, not proof of crawling movement.
- [x] **Present confidence and failure states honestly.** Show the closest supported match, uncertainty and the model score when present; explain when no pose is detected or the confidence threshold is not reached, and provide a helpful retry state instead of implying a successful result. Distinguish a model score from verified correctness.
- [x] **Refine the complete UI/UX.** “Refine the ui/ux to give a nicely designed website” — make the photo upload, preview, analysis progress, result, errors, uncertainty, supported postures and research limitations understandable in an accessible, responsive interface for mobile, tablet and desktop. Prevent duplicate analysis submissions and show visible in-progress feedback.
- [x] **Resolve the uploaded-photo “Not sure yet” case.** When a clear head-up, arms-and-knees pose is visible but feet or a second knee are cropped, require a head at visibility at least 0.30; both shoulders, elbows, wrists and hips in-frame with each landmark at visibility at least 0.25; and one same-side hip-to-knee support pair at visibility at least 0.25. Keep the check narrow, label it as a shape-based estimate when it overrides the model, do not override a learned standing/sitting result, and still report unknown when the relevant support landmarks are unclear.
- [x] **Deliver a working research-preview website and project.** “Fix and make the project. Give me the final working website.” Run the website and required inference service together, verify the upload-to-prediction path, keep photos out of persistent storage, and deliver the working preview and corrected project source. Do not broadly publish the supplied model unless its research/non-commercial terms permit that use.
